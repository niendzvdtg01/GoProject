# Backend

This backend is a REST API built with Go, Gin, MySQL, bcrypt password hashing, and JWT authentication.

The current implementation focuses on identity and user management:

- User registration.
- Login with email and password.
- JWT access token generation.
- Logout by revoking the current token in server memory.
- Authenticated user listing.

Note: the package folder is currently named `respository`. Keep imports consistent unless the package is renamed across the whole codebase.

## Startup Flow

`cmd/main.go` performs the following steps:

1. Loads `.env` from the current directory, then falls back to `Backend/.env`.
2. Reads database configuration from environment variables.
3. Connects to MySQL and configures the connection pool.
4. Creates the user repository.
5. Reads `JWT_SECRET`.
6. Creates auth middleware and services.
7. Registers custom validators.
8. Sets up routes and starts the HTTP server on port `8080`.

## Environment Variables

Create `Backend/.env`:

```env
DB_HOST=localhost
DB_PORT=3311
DB_USERNAME=user
DB_PASSWORD=1234
DB_NAME=miniproject_database
JWT_SECRET=change-this-secret
```

`DB_PORT` is optional. If it is missing or invalid, the backend uses `3311`.

## Database

The `users` table must exist before starting the API:

```sql
CREATE TABLE users (
  user_id VARCHAR(36) PRIMARY KEY,
  username VARCHAR(100) NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

Field notes:

- `user_id`: UUID generated by the server.
- `username`: display name.
- `email`: unique login identifier.
- `password_hash`: bcrypt hash. Raw passwords are never stored.
- `created_at`: creation timestamp.

## API

Base URL:

```text
http://localhost:8080/api
```

### Register

```http
POST /api/users/register
Content-Type: application/json
```

Request body:

```json
{
  "username": "user01",
  "email": "user@example.com",
  "password": "password123"
}
```

Successful response:

```json
{
  "token": "jwt-token",
  "user": {
    "userId": "uuid",
    "username": "user01",
    "email": "user@example.com",
    "created_at": "0001-01-01T00:00:00Z"
  }
}
```

### Login

```http
POST /api/auth/login
Content-Type: application/json
```

Request body:

```json
{
  "email": "user@example.com",
  "password": "password123"
}
```

Successful response:

```json
{
  "token": "jwt-token",
  "user": {
    "userId": "uuid",
    "username": "user01",
    "email": "user@example.com",
    "created_at": "2026-04-30T10:00:00Z"
  }
}
```

### Logout

```http
POST /api/auth/logout
Authorization: Bearer <jwt-token>
```

Successful response:

```json
{
  "message": "logout successful"
}
```

### List Users

Any authenticated user can call this endpoint.

```http
GET /api/users
Authorization: Bearer <jwt-token>
```

Successful response:

```json
{
  "users": [
    {
      "userId": "uuid",
      "username": "user01",
      "email": "user@example.com",
      "created_at": "2026-04-30T10:00:00Z"
    }
  ]
}
```

## Authentication Behavior

- Passwords are hashed with bcrypt.
- JWTs are signed with `HS256`.
- Tokens include `user_id`, `username`, `jti`, `iat`, and `exp`.
- `AuthRequired()` validates `Authorization: Bearer <token>` and stores these values in the Gin context:
  - `user_id`
  - `username`
- Logout stores the token `jti` in an in-memory revocation list until the token expires.

The revocation list is process-local. If the server restarts, previously revoked tokens are no longer remembered.
